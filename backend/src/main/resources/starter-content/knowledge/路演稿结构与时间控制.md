# 路演稿结构与时间控制

## 用途

帮助学生根据已确认的 BP 和 PPT 生成不同长度的路演稿，并在有限时间内保持核心结论一致。本文提供表达和时间控制方法，不提供可直接冒充学生经历的成稿。

## 开始前确认

- PPT 与 BP 的版本
- 路演对象、场合和目标
- 总时长、是否有提问环节
- 学生的自然语速和表达习惯
- 必须讲清的核心结论
- 不能公开的信息与版权限制

未提供真实语速时，时间安排只能作为练习起点，应通过试讲校准。

## 核心叙事

所有时长版本都应回答：

1. 谁在什么场景遇到什么问题
2. 当前替代方案为什么不够
3. 项目用什么机制解决
4. 用户和付费方获得什么结果
5. 有什么证据或当前进展
6. 下一步验证或行动是什么

## 1 分钟版本

适合电梯陈述或开场摘要。建议保留：

- 一个具体问题场景
- 一句话解决方案与差异化
- 一个最有力的证据或待验证指标
- 一个明确的下一步

删除背景铺垫、完整竞品列表和次要功能。

## 3 分钟版本

适合课堂阶段汇报。建议展开：

- 开场与问题
- 方案和用户价值
- 市场/替代方案与差异化
- 商业模式或实施路径
- 验证进展、风险和下一步

每一段对应明确 PPT 页码，转场说明上一结论如何引出下一判断。

## 5 分钟版本

适合完整项目路演。可在 3 分钟版本基础上增加：

- 用户与采购角色区分
- 更完整的市场与竞争证据
- 交付、渠道、资源和财务假设
- 风险、边界和试点计划

增加内容时仍保持结论先行，避免逐页朗读。

## 段落模板

每段记录：

- 对应 PPT 页码
- 本段目标
- 建议时长
- 第一口语句
- 核心结论
- 支持证据
- 转场句
- 可删减内容
- 不可删减内容

## 表达原则

- 使用学生能够自然说出的短句
- 一个句子只承担一个主要意思
- 数字同时说清单位、时间和意义
- 不用“行业领先、巨大市场、颠覆”等无证据形容词
- 遇到未验证事项时明确说“当前假设”和验证计划
- 不把教师反馈、模板文字或 AI 建议冒充团队事实

## 练习与校准

1. 第一次完整计时，不中途修改。
2. 标记超时段、停顿点和难以复述的句子。
3. 优先删除重复解释，再压缩次要证据。
4. 保留用户问题、解决机制、差异化和下一步。
5. 复练并记录版本变化。
6. 把高频卡顿和追问点交给答辩专家训练。

## SCRIPT 阶段交接卡

交给 DEFENSE 和 MEDIA 时至少包含：SCRIPT 版本、采用的 BP/PPT 版本、总时长、核心论点、关键证据、转场、易错点、可复用旁白、待确认内容，并标记 PENDING_STUDENT_CONFIRMATION。
